Cristallisation de l'espace latent

Adaptation au moment du test et arrêt anticipé à risque contrôlé, sur un encodeur vision-langage gelé de type CLIP, en imagerie médicale sous décalage d'acquisition. Terrain de thèse : syndrome de Sjögren, échographie.

L'idée centrale
Traiter l'espace latent d'un modèle CLIP comme un système thermodynamique : les images sont des particules, les classes des puits d'énergie (« ancres »), et la classification une mesure de Gibbs. Les observables physiques (entropie, énergie libre) deviennent des instruments de diagnostic.
Le problème clinique
Un modèle validé sur un échographe donné se dégrade silencieusement quand l'appareil, le réglage ou le centre change. Le décalage d'acquisition est la première cause d'échec du déploiement des modèles en imagerie médicale.
La proposition
L'énergie libre F détecte ce décalage là où l'entropie H (la confiance du modèle) échoue — car F « voit » le niveau absolu des énergies, H seulement leurs écarts relatifs. C'est une prédiction falsifiable, pré-enregistrée avec seuils.

Pourquoi « cristallisation » ?

Par analogie physique : un embedding proche d'une ancre unique est cristallisé (ordre élevé, entropie basse), un embedding équidistant de toutes les ancres est fondu (désordre, entropie maximale). Le paramètre d'ordre $\chi = 1 - H/\ln K$ mesure ce degré de cristallisation entre 0 (fondu) et 1 (cristal parfait).

Trois principes structurants

  1. Le backbone n'est jamais entraîné. Les ancres de classe sont les plongements textuels des invites — disponibles sans GPU sérieux ni annotation. La première mesure du projet est donc zero-shot, zero-training.
  2. Tout est falsifiable et pré-enregistré. Les seuils de verdict sont fixés avant l'expérience. Une réfutation correctement exécutée est un résultat, pas un bug.
  3. Traçabilité totale. Chaque valeur publiée provient d'un outputs/<run_id>/metrics.json portant le commit Git, l'empreinte SHA-256 du code, l'environnement et la configuration complète.

2 · Cadre théorique — la mesure de Gibbs sur la sphère

2.1 Énergie de configuration

Pour un embedding image L2-normalisé $z \in \mathbb{R}^d$ et des ancres textuelles L2-normalisées $\mu_k$ ($k = 1,\dots,K$), l'énergie de la configuration « $z$ appartient à la classe $k$ » est la distance euclidienne au carré :

$$E_k(z) = \lVert z - \mu_k \rVert_2^2 = 2 - 2\langle z, \mu_k\rangle \;\in\; [0, 4]$$

L'identité sphérique $2 - 2\langle z,\mu_k\rangle$ est exacte sur la sphère unité, moins coûteuse et plus stable numériquement que cdist. Plus $z$ est proche de $\mu_k$, plus l'énergie est basse.

2.2 Distribution de Gibbs et équivalence CLIP

La probabilité d'appartenance suit la distribution de Boltzmann-Gibbs à température $T > 0$ :

$$p_k(z) = \frac{\exp(-E_k(z)/T)}{\sum_j \exp(-E_j(z)/T)}$$
⚡ Équivalence exacte avec CLIP
Les logits de CLIP sont $\langle z,\mu_k\rangle/\tau$ où $\tau$ est sa température apprise. Comme $E_k = 2 - 2\langle z,\mu_k\rangle$, les deux softmax sont identiques pour $T = 2\tau$. L'inférence zero-shot de CLIP est une mesure de Gibbs — ce n'est pas une approximation, c'est vérifié à la précision machine par tests/test_clip_equivalence.py.

2.3 Les quatre observables

ObservableDéfinitionIntuition physiqueRôle diagnostique
Entropie $H$$-\sum_k p_k \ln p_k$ Désordre de la répartitionConfiance du modèle — invariante par translation des énergies
Énergie libre $F$$-T\ln\sum_k e^{-E_k/T}$ Potentiel thermodynamique $-T\ln Z$Covariante : détecte l'éloignement absolu de toutes les ancres
Énergie moyenne $\langle E\rangle$$\sum_k p_k E_k$ Énergie interneFerme l'identité thermodynamique
Cristallinité $\chi$$1 - H/\ln K$ Paramètre d'ordre $\in [0,1]$0 = fondu (équiprobable), 1 = cristal (certitude)
Invariant logiciel — l'identité thermodynamique, testée à la précision machine : $$F = \langle E\rangle - T\,H$$

2.4 Proposition 2 — le cœur de la prédiction falsifiable

Soit une translation uniforme des énergies $E_k \mapsto E_k + c$ (toutes les classes s'éloignent d'autant). Alors :

$$p_k \mapsto p_k \quad(\text{inchangé}), \qquad H \mapsto H \quad(\text{inchangée}), \qquad F \mapsto F + c \quad(\text{translatée})$$

Un décalage d'acquisition (nouvel échographe, réglage différent) éloigne typiquement les images de toutes les ancres sans bouleverser les écarts relatifs entre classes. Le modèle reste donc confiant (H basse) tout en étant hors de son domaine (F élevée). C'est le scénario le plus dangereux en clinique : l'erreur silencieuse et assurée.

🎯 Critère pré-enregistré (expérience 1, sévérité maximale)
  • $\operatorname{AUROC}(F) \ge 0{,}70$ — F sépare source et cible ;
  • $\operatorname{AUROC}(H) \le 0{,}60$ — H échoue, proche du hasard ;
  • $\operatorname{AUROC}(F) - \operatorname{AUROC}(H) \ge 0{,}05$ — l'écart est matériel.
Limites de portée — assumées
Rien ne garantit que tout décalage augmente F, ni que H reste toujours au hasard. La validité dépend du modèle, des invites, de la cohorte et de la corruption. Si la prédiction ne tient pas, le résultat se consigne tel quel : c'est une réfutation, pas un bug.

6.2 Les corruptions locales — physiquement motivées par l'échographie

Speckle
Bruit multiplicatif $a \cdot (1+\mathcal{N}(0,\sigma_s))$ — l'artefact caractéristique de l'échographie, σ de 0,08 à 0,52 selon la sévérité.
Flou
Convolution séparable à noyau croissant — défaut de focalisation ou de résolution de sonde.
Gain
Contraction de contraste + décalage de luminosité — réglage d'appareil différent entre centres.
Gamma
Compression dynamique $255\,(a/255)^{\gamma}$, γ de 1,2 à 2,5 — préréglage constructeur.

8 · Code annoté — les fonctions qui portent la théorie

def squared_distances(z, mu, normalized=True):
    # Identité sphérique : ||z-μ||² = 2 - 2⟨z,μ⟩ sur la sphère unité.
    # Exacte, moins coûteuse et plus stable que cdist. clamp_min contre
    # les négatifs d'arrondi flottant.
    if normalized:
        return (2.0 - 2.0 * (z @ mu.t())).clamp_min(0.0)
    return torch.cdist(z, mu, p=2).pow(2)

def gibbs(z, mu, T, normalized=True):
    # log_softmax, JAMAIS softmax puis log : stabilité numérique.
    d2 = squared_distances(z, mu, normalized)
    return torch.log_softmax(-d2 / T, dim=-1), d2

def free_energy(d2, T):
    # F = -T ln Z. Contrairement à H, F dépend du niveau ABSOLU des
    # énergies : c'est ce qui lui permet de signaler un échantillon
    # éloigné de toutes les ancres, même si le modèle est confiant.
    return -T * torch.logsumexp(-d2 / T, dim=-1)

def crystallinity(H, K):
    # Paramètre d'ordre χ = 1 - H/ln K ∈ [0, 1].
    return 1.0 - H / math.log(K)

Toutes les fonctions sont différentiables et opèrent par lots — condition nécessaire pour la future adaptation au moment du test, où F devient un terme de perte.

@torch.no_grad()
def anchors(self, prompts, ensemble=True):
    # Les ancres ne sont PAS apprises : ce sont les plongements textuels
    # des invites. L'ensemble moyenne les formulations d'une même classe
    # puis renormalise — baseline forte et gratuite (ligne A1).
    out = []
    for phrases in prompts.phrases():
        chosen = phrases if ensemble else phrases[:1]
        tok = self.tokenizer(chosen).to(self.device)
        emb = F.normalize(self.model.encode_text(tok).float(), dim=-1)
        out.append(F.normalize(emb.mean(0), dim=-1))
    return torch.stack(out)   # (K, d), L2-normalisé

Le décorateur @torch.no_grad() et le gel de tous les paramètres (requires_grad_(False)) matérialisent la règle : l'encodeur texte et les ancres appartiennent à theta_frozen, toujours.

def temperature_from_logit_scale(logit_scale):
    # CLIP stocke logit_scale tel que logits = exp(logit_scale)·⟨z,t_k⟩,
    # donc τ = 1/exp(logit_scale). L'équivalence du cadre théorique :
    #   softmax(⟨z,μ⟩/τ) = softmax(-(2-2⟨z,μ⟩)/T)  ⟺  T = 2τ
    ls = float(logit_scale.detach().cpu()) if ...
    return 2.0 / math.exp(ls)

C'est le pont exact entre la vue « produit scalaire » de CLIP et la vue « énergie/distance » thermodynamique. Vérifié à la précision machine par test_clip_equivalence.py. Toute recalibration de T se fait sur la validation source et l'écart à 2τ est rapporté.

Chaque metrics.json embarque le commit Git, son état dirty, l'empreinte SHA-256 du code exact, l'environnement et la config complète. Le run_id lui-même contient un hash de la configuration : impossible de confondre deux runs.

Pièges connus — la mémoire du projet (CLAUDE.md)

  1. Les forward hooks ne peuvent pas interrompre le calcul : l'arrêt anticipé exige une boucle explicite sur les blocs du ViT.
  2. Ne jamais adapter l'encodeur texte dans la voie par défaut : les ancres doivent rester fixes.
  3. Latence : échauffement + torch.cuda.synchronize() + cuda.Event.
  4. Les FLOPs incluent les passes arrière (~2× l'avant) et, pour TPT, les dizaines de vues augmentées.
  5. theta_adapt est restauré après chaque lot : une dérive entre patients est un bug.
  6. Les invites sont figées sur la validation source — les choisir au vu des cibles est une fuite.
